## Инварианты проекта — любое нарушение считать багом
1. Списки, даты и статусы строит код, а не LLM. Модель только формулирует текст.
2. Модель ничего не записывает в данные сама. Задачи, обещания и наблюдения о пользователе создаются только после нажатия кнопки.
3. Дата события ≠ время напоминания (`event_date` у задач `reminder_only`).
4. Пары Modeus и вебинары Нетологии — разные занятия, их нельзя дедуплицировать.
5. Напоминание исчезает только когда пользователь сам его закрыл; по истечении повторов оно остаётся (`exhausted`).
6. Закрытие задачи из любого места идёт через `task_actions.complete_task` и откатывается через `undo_action`.
7. Ни один вызов Claude не использует `--resume` дневной сессии.
8. Оценка `0` из Modeus означает «не выставлено», это не двойка.
9. Всё время — в поясе `Asia/Yekaterinburg` (`config.UFA_TZ`).
10. Репозиторий публичный: в коде не должно быть личных данных (ФИО, группы, преподаватели, токены, пути `/Users/...`). Они живут в `.env` и `data/`.

## Что особенно проверить
- **Конкурентность.** Бот, launchd-скрипты и окно на Swift пишут одни и те же `data/*.json` и `data/agent.db`. Проверь:
  - порядок блокировок `file_lock` (tasks → reminders, flock не реентерабелен — возможен ли самоблок?);
  - атомарность записей;
  - короткие транзакции SQLite.
- **Миграции `agent_db`:** v1→v2 на существующей базе, бэкап перед миграцией.
- **FTS5:**
  - синхронизация через триггеры (`raw_events_fts`) и `rebuild` (`knowledge_fts`);
  - безопасность пользовательского ввода в `MATCH` (функция `fts_query`).
- **Telegram-обработчики:**
  - проверка владельца (`is_authorized`) в `button_callback`;
  - повторное нажатие кнопок;
  - устаревшие токены в `context.user_data`;
  - длинные ответы (`_split_message`, лимит 4096).
- **Лимиты сообщений по поводу (`agent_triggers.py`):**
  - не больше 2 в день, пауза 3 ч;
  - повтор одного повода через `notification_state`;
  - тихие часы;
  - рост порога от 👎;
  - что будет при падении между отправкой и записью в базу.
- **`agent_extract.py`:**
  - фильтр шума (не теряются ли важные письма преподавателей);
  - разбор JSON от модели;
  - проверка дублей задач (`_already_tracked`);
  - поведение при ошибке модели.
- **`mentor_deep.py`:** качество поиска фрагментов (вес редких слов), бюджеты символов, отсутствие инструментов у модели.
- **Окно на Swift (`main.swift`):**
  - проверка nonce и origin в `WKScriptMessageHandler`;
  - регулярка для id;
  - ограничение частоты действий;
  - отложенная перезагрузка (`mentorCanReload`);
  - один экземпляр через flock;
  - вычисление `projectDir` из пути бинарника.
- **Мёртвый код и устаревшие комментарии** после рефакторинга. Например, `run_claude_session` больше не используется; проверь ссылки на удалённые функции и константы — один кусок `scripts/mentor_checkin.py` во время работы восстанавливался вручную.
- **Расход токенов:** нет ли пути, где сводка неограниченно растёт или модель снова получает инструменты чтения файлов.

## Как проверять безопасно — обязательно
- НЕ отправляй сообщения в Telegram, не запускай `./start.sh`, не делай `launchctl`, не делай `git push` и `git commit`.
- НЕ изменяй `data/` и `.env`. Для экспериментов с базой копируй `data/agent.db` во временную папку и подменяй `agent_db.DB_PATH`.
- Чек-ины проверяй только с `--dry-run`, например:
  ```bash
  venv/bin/python3 scripts/mentor_checkin.py morning --dry-run
  ```
- Вызовы Claude тратят лимит подписки. Делай не больше 3–4 живых вызовов, остальное проверяй чтением кода и тестами с заглушками (`run_claude_oneshot`, `send_telegram`).
- Можно запускать:
  ```bash
  venv/bin/python3 -m py_compile <файлы>
  ```
  ```bash
  swiftc -typecheck scripts/native_widget/main.swift
  ```
  а также импорт модулей и функции без побочных эффектов: `build_checkin_pack`, `build_chat_pack`, `build_materials`, `fts_query`, `normalize_ts`, `compute_streak`, `_split_message`.
